# T2 — Scenario Explorer Raw Report

## 원본 질문 (요지)

> 이 앱이 커버할 사용 시나리오의 전체 지형 스캔. 경쟁 환경·대안 도구·시나리오 우선순위 결정. 홍보 범위(부부·고부·직장)와 기능 범위(연인) 비대칭 관리.

## 조사 방법론

- **시나리오 수집**: Gottman Institute 연구 문헌, 한국 커플 상담 사례 보고(2020-2025), Reddit r/relationship_advice·에브리타임·블라인드의 공개 질문 경향성 분석(양적 집계 수준, 개인정보 미수집).
- **경쟁 분석**: 글로벌(Replika, Lasting, Paired, Relish, Character.ai, BetterHelp), 한국(카카오 i 코치, 마음건강검진, Wysa 한국어, 트로스트), 전통 오프라인 상담(한국상담심리학회 회원 기관) 3축.
- **시나리오×Branch 매트릭스**: 각 시나리오를 Branch A·B에서 어떻게 커버 가능한지 기술적·프라이버시적·UX적 관점으로 평가.
- **법적·윤리적 경계**: self-help coaching 포지셔닝 유지를 위한 시나리오 필터링 기준 명시.

## §1. 연인(Dating Couples) 갈등 시나리오 지형도

연인 관계는 T2의 **1순위 기능 범위** (ADR-0002). 본 섹션은 갈등 유형을 체계적으로 분류하고 각 유형의 특성·발생 빈도·앱 개입 가능성을 정리한다.

### 1.1 갈등 유형 분류 (8대 카테고리)

Gottman Institute의 4 Horsemen(비난·방어·담쌓기·경멸)을 상위 축으로, 한국 연인 관계 특유 맥락을 하위 축으로 매핑.

- **C-1. 일상 소통 오해 (Everyday Misunderstanding)**
  - 예: 카톡 답장 속도·이모티콘 해석·약속 시간 변경.
  - 빈도: 주 2-5회. 가장 흔한 저강도 갈등.
  - 앱 개입 적합도: **높음**. 대화 전 "지금 메시지 괜찮을까?" 체크·완화 표현 제안.
  - Tier 라우팅: Tier 1(로컬) 충분.

- **C-2. 기대치 불일치 (Expectation Gap)**
  - 예: 기념일 챙기는 정도·연락 빈도·데이트 주도권·친구 모임 참석 기대.
  - 빈도: 주 1-3회, 특히 연애 초기 3-6개월.
  - 앱 개입 적합도: **높음**. NVC의 "관찰-감정-필요-요청" 4단계 가이드 효과적.
  - Tier 라우팅: Tier 1 기본, 감정 격해지면 Tier 2.

- **C-3. 질투·신뢰 (Jealousy & Trust)**
  - 예: 이성 친구 만남·SNS 좋아요·구 연인 연락·회식 참석.
  - 빈도: 월 1-2회 (커플마다 편차 큼).
  - 앱 개입 적합도: **중간**. 근거 없는 의심 vs 실질적 불안 구분이 필요. 잘못된 조언은 관계 악화.
  - Tier 라우팅: Tier 2 우선 (맥락 복잡성).

- **C-4. 금전·가치관 (Money & Values)**
  - 예: 데이트 비용 분담·선물 가격·저축 습관·경제력 차이.
  - 빈도: 월 1-2회.
  - 앱 개입 적합도: **중간**. 금전 갈등은 결혼 후 이혼 사유 Top 3. 조기 소통 훈련 가치 큼.
  - Tier 라우팅: Tier 2.

- **C-5. 가족·친구 개입 (Family & Friends Involvement)**
  - 예: 부모 반대·친구가 파트너 싫어함·가족 모임 갈등·결혼 압박.
  - 빈도: 분기 1-2회, 결혼 임박기 급증.
  - 앱 개입 적합도: **중간**. 한국 특수(부모 영향력·유교 가치관) 고려 필수.
  - Tier 라우팅: Tier 2-3 (문화 맥락 필요).

- **C-6. 이별·관계 재평가 (Breakup Consideration)**
  - 예: "이 관계 맞는 건가?"·권태기·장기 불만족.
  - 빈도: 관계 당 1-3회 사이클.
  - 앱 개입 적합도: **높지만 조심스러움**. "헤어져" 조언 남용 금지(Reddit 60% 현상 회피). 관계 지속 vs 종료 중립적 의사결정 지원.
  - Tier 라우팅: Tier 3 (인간 개입 권장).

- **C-7. 친밀감·애정 표현 (Intimacy & Affection)**
  - 예: 스킨십 온도차·말로 표현하는 사랑·성적 욕구 불일치.
  - 빈도: 월 1-2회 또는 만성.
  - 앱 개입 적합도: **중간**. 성적 내용은 자체 검열 · App Store 심사 민감.
  - Tier 라우팅: Tier 2, 성적 주제는 금지 필터 적용.

- **C-8. 위기 징후 (Crisis Signals)**
  - 예: 언어·정서·신체적 학대, 자해/자살 언급, 스토킹, 감정 조작(gaslighting).
  - 빈도: 낮지만 위험도 극대.
  - 앱 개입 적합도: **절대 자체 해결 금지**. 즉시 전문 기관 리퍼럴.
  - Tier 라우팅: Tier 3 + 의무적 핫라인 안내 (1366·1577-0199·112·1393).

### 1.2 갈등 라이프사이클 단계

하나의 갈등이 시간 축에서 어떻게 진행되는지:

1. **촉발 (Trigger)** — 특정 사건·메시지·상황.
2. **감정 반응 (Reaction)** — 화·상처·방어·회피. 생리적 각성(Flooding).
3. **의사소통 시도 (Attempt)** — 말다툼·침묵·카톡 공방.
4. **교착 또는 해소 (Stalemate or Resolution)** — 화해·사과·미해결 누적.
5. **사후 감정 (Aftermath)** — 재발 우려·관계 재평가·학습.

앱 개입 지점은 각 단계별로 다름:
- 1단계: 촉발 탐지 (패턴 학습).
- 2단계: **자기 진정 가이드** (격앙 상태에선 상대에게 말하기 전 멈추기).
- 3단계: **대화 스크립트 제안** (비난→관찰, 공격→요청 번역).
- 4단계: **화해 루틴 제안** (Gottman repair attempts).
- 5단계: **성찰 저널** (무엇이 효과적이었나, 다음엔 무엇을).

### 1.3 한국 연인 관계 특수 요소

- **메신저 중심 소통**: 카카오톡이 대화 비중 60%+. 텍스트 맥락 손실·오해 증폭이 큰 문제. 앱은 **메시지 작성 보조** 기능이 특히 가치.
- **유교 문화 잔재**: 감정 직접 표현의 어려움, "알아주길 기대"하는 암묵 소통. NVC의 명시적 표현 훈련이 문화적 저항에 부딪힐 수 있음.
- **결혼 압박 연령대(20대 후반-30대 초반)**: 부모·친척·사회의 결혼 시기 압박이 연인 갈등의 배경 변수. C-5·C-6와 교차.
- **군대 복무**: 장거리 연애·단절 경험이 20대 커플에 흔함. 복무 중/직후 재적응 갈등은 한국 특유 시나리오.
- **회식·야근 문화**: 파트너의 업무 시간·회식 빈도 갈등. 블라인드·잡플래닛 후기에 빈번히 등장.

### 1.4 시나리오별 데이터셋 요구

각 시나리오를 앱이 다루려면 **학습/참조 데이터**가 필요. 현실적 획득 경로:

- 공개 문헌: Gottman 논문, NVC 사례집, 임상심리학 교재.
- 합성 데이터: T1 §3 NO-2와 연동. 전문가 감수 하에 합성 대화 생성 (`@synthetic-dialogue-generator`).
- 한국어 말뭉치: 국립국어원 공개 말뭉치(격식체 편향) · 오픈소스 커뮤니티 공개 데이터(저작권·동의 이슈 파킹).
- 자문단 직접 제작: 커플 상담사·임상심리사와 협업 (T3/T4 §8 자문 연계).

## §2. 홍보용 다른 관계 유형 — 부부·고부·직장 시나리오

ADR-0002: **연인이 1순위 기능**, 부부·고부·직장은 **홍보 범위에 동시 포함**. 이 비대칭은 "마케팅에 끌려 들어온 유저가 기능 범위에서 실망"하는 리스크를 낳는다(미해결 축 R1). 본 섹션은 각 관계 유형의 시나리오 지형을 **홍보 카피 재료 + Phase 2 확장 근거**로 정리.

### 2.1 부부 관계 시나리오 (Married Couples)

연인과 공통 갈등 범주(C-1~C-8)는 대부분 적용되지만, 부부 특유 변수가 추가된다.

- **M-1. 가사·육아 분담**: 맞벌이 증가로 분담 불균형 갈등 빈도 급증. 2024 통계청 "생활시간조사"에서 여성 가사 노동 시간 남성 대비 3배.
- **M-2. 양가 가족 관계**: 명절·경조사·시댁/처가 방문 빈도·선물·대화 톤. 고부 관계(§2.2)와 중첩.
- **M-3. 경제 운영**: 공동 통장·개인 용돈·주택 대출·자녀 교육비 배분.
- **M-4. 부부 성관계**: 빈도·만족도·외도 의심. 앱 직접 개입 매우 제한적(App Store 심사·자체 검열).
- **M-5. 이혼 고려**: 법적·경제적·자녀 영향 복잡성. 앱은 **자기 정리 + 전문 상담 리퍼럴** 역할에 한정.
- **M-6. 자녀 양육관 차이**: 훈육 방식·교육 철학·유학 여부.

홍보 카피 재료 예시:
- "결혼 5년, 같은 말 또 싸우고 있다면" (M-1·M-6 타겟).
- "명절 후 부부 냉전, 올해는 다르게" (M-2 타겟).

확장 시 기능 차이:
- 연인 기능을 재사용하되 **도메인 페르소나 레이어**로 맥락 주입(§1.2의 Gottman 4단계 + 부부 특유 어휘·사례).
- 공유 모드 UX는 더 중요 — 부부는 이미 재정·자녀·가족을 공유하므로 공동 사용 인센티브 높음.

### 2.2 고부(시부모·시가)/처가 관계 시나리오

한국 특유 관계 유형. 유교 문화·가족 위계·언어 예절이 결정 변수.

- **L-1. 명절 스트레스**: 방문 빈도·음식 준비·귀성 이동·친척 참석 압박.
- **L-2. 호칭·예절**: 결혼 초기 호칭 전환(오빠→여보, 어머님/어머니 등) 스트레스, 존댓말 강도.
- **L-3. 경제 개입**: 자녀 세대에 대한 경제적 기대·지원·차별.
- **L-4. 육아 개입**: 양육 방식 간섭·양가 역할 불균형.
- **L-5. 감정적 부채감**: "어머님이 서운해하신다"형 간접 압박, 배우자 경유 전달.
- **L-6. 세대·젠더 가치관 충돌**: "며느리/사위는 이래야"형 전통 기대 vs 현대 가치관.

홍보 카피 재료 예시:
- "시어머니 톡 하나에 하루 종일 울컥한다면" (L-5 타겟).
- "명절만 다가오면 부부 싸움 시작" (L-1·M-2 교차).

확장 시 기능 차이:
- **비대면 간접 갈등** 비중 큼 — 본인은 상대와 직접 대화하지 않고 배우자 통해 전달됨. 앱은 "배우자에게 상황 설명하는 스크립트"에 특화 기능.
- **문화 맥락 민감도**: 시가·처가 어휘·호칭·예절을 정확히 모르면 앱 조언이 현실감 없음. 한국어 특화 모델·전문가 감수 필수.
- **자녀 세대(유저) 관점 고정**: 앱 사용자는 주로 며느리·사위·자녀 세대. 시부모 세대 유저는 소수 — 기능·UX 설계 기준 세대는 30-40대.

### 2.3 직장(상사·동료·후배) 관계 시나리오

가장 넓은 유저 풀·가장 높은 빈도 갈등 도메인. 단 "관계 코칭"의 친밀도 전제와 다소 결이 다름.

- **W-1. 상사와의 소통**: 피드백 해석·업무 지시 모호성·평가 피드백·퇴근 압박.
- **W-2. 동료 간 갈등**: 업무 분담·협업 스타일 차이·팀 내 파벌.
- **W-3. 후배·부하 관리**: 지시 톤·세대 차이·성과 피드백.
- **W-4. 회식·비공식 모임**: 참석 의무감·술자리 스트레스·뒷담화.
- **W-5. 직장 괴롭힘(bullying)**: 법적 보호 영역 근로기준법 제76조의2. 앱 자체 해결 금지, 법률 상담·HR·노동청 리퍼럴.
- **W-6. 퇴사·이직 결정**: 커리어 맥락. 관계 코칭보다는 커리어 코칭 경계.

홍보 카피 재료 예시:
- "팀장님 한마디에 일주일을 곱씹는다면" (W-1 타겟).
- "동료랑 일은 하는데 마음은 멀어진다" (W-2 타겟).

확장 시 기능 차이:
- **감정 소화 vs 관계 복원** 비중 전환. 직장 관계는 이탈(이직)이 항상 옵션이라 "반드시 복원"이 목표 아님. 앱은 **감정 처리 + 소통 스크립트**가 주. 장기 관계 개선은 부차.
- **괴롭힘 탐지 민감도**: W-5에 해당하는 표현("계속 배제한다"·"모욕적인 말을 듣는다")이 포착되면 즉시 **공식 구제 경로**(고용노동부 1350·직장갑질119·법률상담) 안내. 앱이 "참아라"·"이해해줘라"형 조언을 내놓으면 법적·윤리적 리스크.
- **프라이버시 리스크 증가**: 직장 대화는 회사 소속·동료 실명이 포함되기 쉬움. Branch B 전송 시 가명화 필수.

### 2.4 홍보-기능 gap 관리 전략

R1 미해결 축의 해결 후보. 본 조사에서 다음 4개 전략을 비교.

- **전략 1. 홍보 메시지를 연인 중심으로 좁힘**: ASO 방어에 안전하나 ADR-0002 의도(넓은 홍보)와 충돌.
- **전략 2. 다른 관계 유형 "베타 뱃지" 공개**: 앱 내 부부·고부·직장 섹션을 베타로 표시하고 제한 기능 명시. 유입 유지 + 실망 완화. **권장**.
- **전략 3. 유입 소스별 분기 온보딩**: 광고 크리에이티브·랜딩 페이지별로 기대치 다르게 설정. 구현 복잡도 중간.
- **전략 4. Phase 2 확장 일정 공개**: 앱 내 "곧 출시" 섹션 + 이메일 대기 등록. 페르소나 연결·리텐션·마케팅 가치 결합.

**종합 권장**: 전략 2 + 4 조합. 전략 1은 Phase 1 신뢰 획득 전까지 보조로 유지.

### 2.5 다관계 동시 관리의 기술적 함의

동일 유저가 연인·부부·고부·직장 갈등을 혼재 입력할 수 있다. 이 경우:

- **세션·대화 태깅**: 각 세션에 `relation_type` 메타데이터. UI에서 필터·검색.
- **도메인 페르소나 레이어**: T2 제안(§2.2·§2.3)의 공유 코어 엔진 + 도메인 오버레이. 코칭 프레임워크는 공통(Gottman/NVC), 어휘·예시·감정 태그만 도메인별 교체.
- **유저 프로파일**: 관계 유형별 활성 사용 기간·빈도 추적으로 개인화 힌트 생성.

## §4. 시나리오 × Branch 매트릭스

§1·§2의 시나리오가 Branch A(Privacy-First Local) vs Branch B(Cloud-Native Feature-Rich)에서 어떻게 다르게 구현되는지 평가. **각 셀은 "구현 가능성 / 프라이버시 적합도 / 체감 품질"** 3축 점수(5점 척도).

### 4.1 연인 시나리오 매트릭스 (C-1 ~ C-8)

| 시나리오 | Branch A (구현/프라이버시/품질) | Branch B (구현/프라이버시/품질) | 비고 |
|---|---|---|---|
| C-1 일상 소통 오해 | 5/5/4 | 5/3/5 | A가 주도, Tier 1 적합 |
| C-2 기대치 불일치 | 4/5/4 | 5/3/5 | Hybrid Tier 1→2 에스컬레이션 이상적 |
| C-3 질투·신뢰 | 3/5/3 | 5/3/5 | 맥락 복잡 — Tier 2 권장 |
| C-4 금전·가치관 | 3/5/3 | 5/3/5 | 금전 맥락 정교함 필요 |
| C-5 가족·친구 개입 | 2/5/2 | 5/3/4 | 한국 문화 맥락 깊이 필요 |
| C-6 이별·관계 재평가 | 2/5/2 | 4/3/4 | Tier 3(인간) 필수 |
| C-7 친밀감·애정 표현 | 3/5/3 | 4/3/4 | 성적 주제 필터 필요 |
| C-8 위기 징후 | 1/5/1 | 3/4/3 | **앱 자체 해결 금지** — 리퍼럴만 |

**해석**:
- **구현 가능성**: Branch A는 로컬 LLM 한계로 복잡 시나리오(C-3~C-6)에서 품질 하락. Branch B는 전반 5점.
- **프라이버시 적합도**: A는 모든 시나리오에서 최고(5). B는 암호화·동의 체계로 3점 유지.
- **체감 품질**: A는 단순 시나리오(C-1·C-2)에서 충분. 복잡 시나리오는 B 우세.

### 4.2 홍보 시나리오 매트릭스 (M·L·W)

| 시나리오 | Branch A | Branch B | 비고 |
|---|---|---|---|
| M-1 가사·육아 분담 | 3/5/3 | 5/3/5 | 부부 공유 모드 B에서 쉬움 |
| M-2 양가 가족 관계 | 2/5/2 | 5/3/4 | L과 중첩, 문화 맥락 심층 |
| M-3 경제 운영 | 3/5/3 | 5/3/4 | 금전 모델링 B 우세 |
| M-4 부부 성관계 | 2/5/2 | 3/3/3 | 양측 심사 필터 필요 |

## §5. 시나리오 우선순위 4축 평가

§4 매트릭스는 "기술 구현 가능성·프라이버시·체감 품질"을 봤다. §5는 **시장·사업·법적** 관점으로 다시 우선순위를 매긴다. 최종 v1 feature 선정은 **§4 점수 × §5 4축 가중치**로 도출된다.

### 5.1 4축 정의

- **A1. 시장 크기 (Market Size)**: 해당 시나리오에서 고통을 겪는 유저 수. 1-5점 (5 = 한국 연인 전체의 50%+ 동시 경험).
- **A2. 즉시 지불 의향 (Willingness-to-Pay Urgency)**: 시나리오 발생 시 유저가 **즉시** 도움에 돈을 지불할 가능성. 1-5점.
- **A3. 법적·윤리 안전 (Safety Margin)**: 오조언·오작동 시 법적·윤리적 리스크의 **낮음** 정도. 5 = 매우 안전, 1 = 사고 즉시 소송 리스크.
- **A4. 차별화 가능성 (Differentiation)**: 본 제품이 경쟁사(§3)와 비교했을 때 독특한 가치를 제공 가능한 정도. 1-5점.

각 시나리오의 4축 점수를 합산·가중평균(A1 0.3·A2 0.3·A3 0.25·A4 0.15)해 우선순위 산출.

## §6. Self-Help Coaching 경계선 정의

ADR-0003: 본 제품은 **self-help coaching** 포지셔닝. 임상 상담·의료 행위 회피가 법적 안전 테두리. 본 섹션은 경계선을 **허용/금지/조건부 허용** 3구역으로 명시하고, 각 구역별 앱 UX·카피·기능을 규정한다.

### 6.1 허용 영역 (Allowed — 자유 기능)

다음 표현·기능은 self-help coaching의 정상 범위.

- **감정 단어 사용**: "불안해요"·"서운해요"·"화나요"·"지치네요" 같은 일상 감정 어휘. 유저 자기 보고 그대로 수용.
- **관계 프레임워크 안내**: Gottman 4 Horsemen·NVC 4단계·IFS parts·Attachment style 등 **공개 학술 개념의 요약 설명**.
- **커뮤니케이션 스크립트 제안**: "다음과 같이 말해볼 수 있어요: ~"형 문장 생성.
- **자기 성찰 질문**: "이번 상황에서 가장 중요했던 가치는 무엇인가요?" 같은 코칭 질문.
- **정보 제공**: "연인 갈등에서 Flooding이 일어나면 20분 휴식 후 대화를 재개하는 것이 도움 된다는 연구가 있어요."
- **행동 실험 제안**: "오늘 저녁에 '고마워'라는 말을 한 번 해보기" 등 가벼운 과제.
- **저널·기록 기능**: 유저가 스스로 감정·사건을 기록하는 도구. 앱은 편집·질문만 제공.
- **공개 자원 안내**: 정신건강복지센터 위치·연락처, 정부 무료 상담 서비스, 도서 추천.

### 6.2 금지 영역 (Prohibited — 절대 금지)

다음 표현·기능은 **Hook으로 exit 2 차단**(T1 C2).

- **진단 표현**: "당신은 우울증입니다"·"ADHD 증상이에요"·"경계성 인격장애 같아요"·"PTSD로 보여요".
- **의학적 판단**: "이건 화학적 불균형이에요"·"세로토닌 부족일 수 있어요"·"유전적 성향이에요".
- **치료 선언**: "이 앱으로 관계가 치유됩니다"·"이걸 하면 불안장애가 나아져요".
- **처방·권고**: "정신과 약을 바꿔보세요"·"병원 가지 마세요"·"상담사 그만두세요".
- **DSM-5·ICD-11 용어 직접 적용**: "narcissistic personality disorder 같아요"·"OCD 스펙트럼이에요" 등.
- **'상담'·'치료'·'임상' 명사 단독 사용**: "AI 상담을 시작합니다"·"치료 세션"·"임상 심리 평가".
  - 허용 우회: "코칭 세션"·"자기 이해 가이드"·"감정 탐색 질문".
- **특정 진단·질환의 치료 효과 주장**: "우울증에 효과"·"불안장애 개선" — 의료기기 심사 대상 경계.

### 6.3 조건부 허용 영역 (Conditional — 맥락·동의·면책 조건부)

- **감정 강도 자가 평가 스케일 (1-10)**: **허용**. 단 PHQ-9·GAD-7 등 **검증된 임상 척도는 금지**(검증된 척도 사용 시 심리검사 행위 해석 가능).
- **"휴식"·"거리두기"·"명상" 권유**: **허용**. 단 "이완 요법"·"치료적 개입"·"처방 활동" 등 의료 용어는 금지.
- **커플 상담 권유 문장**: **허용**. 단 "전문 상담을 받으셔야 합니다"보다 "전문가와 이야기해보는 것이 도움될 수 있어요"처럼 **권유형·선택지 제공형**.
- **감정 조절 기법 안내**: **허용**. 단 "CBT 기법" 같은 학술 명 앞세우기보다 "생각 다시 바라보기"·"심호흡"·"근육 이완" 같은 일상어로.
- **과거 상처·트라우마 경험 언급 허용 여부**: **조건부**. 유저가 스스로 언급한 것은 경청. 앱이 **트라우마 처리 프로세스**를 주도하면 금지 — "충분히 힘드셨겠어요" 공감 후 전문가 안내로 연결.
- **성격 유형 언급**: MBTI·애착유형은 **허용**(대중적 용어). Big Five는 조건부. 임상 진단명은 금지.

## §7. Crisis 리퍼럴 프로토콜 (한국 특화)

관계 갈등 앱에서 가장 높은 법적·윤리적 리스크는 **위기 신호를 놓치는 것**. Character.ai 2024 선례가 그 증거(§3.4). 본 섹션은 위기 탐지·대응·리퍼럴의 한국 맥락 구체화.

### 7.1 위기 분류 (3단계)

- **Level 1 — 즉각 위험 (Acute Risk)**
  - 키워드 예: "죽고 싶어요", "더 이상 못 버틸 것 같아요", "자해를 했어요", "지금 너무 위험한 상황이에요", "맞아서 다쳤어요", "칼이 있어요".
  - 타인 위험 키워드: "그 사람을 해치고 싶어요", "죽여버릴 거예요", "아이가 맞고 있어요".
  - 대응: **즉시 응급 안내 카드** + 대화 일시 중단 + 외부 핫라인 번호·링크.

- **Level 2 — 심각 징후 (Serious Distress)**
  - 키워드 예: "살고 싶지 않아요", "잠이 안 와요 2주째", "밥도 못 먹겠어요", "매일 울어요", "그 사람 없이는 못 살아요", "돌아갈 곳이 없어요".
  - 패턴: 2주 이상 지속 고통·일상 기능 훼손·관계 의존적 자기 가치.
  - 대응: 공감 응답 + **전문가 상담 강력 권유 카드** + 자원 링크.

- **Level 3 — 경도 고통 (Mild Distress)**
  - 일반 연인 갈등·일시적 스트레스. 앱의 주 서비스 영역.
  - 대응: 평상 코칭 흐름 + 필요 시 전문 상담 **선택지 안내**.

### 7.2 한국 크라이시스 리소스 (2026-04 기준)

다음 번호·기관을 앱 내 **하드코딩**(`app/content/crisis-resources.ko.json`). 핫라인은 서버 요청 없이 로컬에 상시 내장.

- **자살예방상담전화 1393** (24시간, 무료, 정부)
- **여성긴급전화 1366** (여성 대상 폭력·가정폭력·성폭력, 24시간)
- **정신건강상담전화 1577-0199** (정신건강복지센터, 24시간)
- **청소년전화 1388** (19세 미만 대상)
- **범죄신고 112** (즉시 위험)
- **소방·구급 119** (신체 응급)
- **한국생명의전화 1588-9191** (24시간, 민간)
- **다누리콜센터 1577-1366** (이주여성·다문화가정)
- **해바라기센터** (성폭력·가정폭력·성매매 피해자 지원, 지역별 운영)
- **가정폭력·성폭력 상담소 목록** (여성가족부 공식 링크)

### 7.3 위기 응답 UX 스펙

위기 탐지 시 UI/UX 동작 시퀀스:

1. **응답 생성 중단**: LLM 응답이 생성 중이어도 즉시 대체 플로우 전환.
2. **위험 인식 카드 표시**: 상단에 하이라이트 카드. 톤은 **침착·공감·비재촉**.
   - 예시 문구: "지금 많이 힘드신 것 같아요. 혼자 감당하기 어려운 상황이 느껴져요. 지금 바로 도움을 받을 수 있는 곳이 있어요."
3. **핫라인 버튼 2-3개 우선 노출**: 탭하면 전화 앱 즉시 호출(tel:1393).
   - 여성 폭력 맥락 → 1366 우선.
   - 청소년 → 1388 우선.
   - 자살 언급 → 1393 우선.
4. **추가 자원 접기 옵션**: "더 많은 도움 자원 보기" → 해바라기센터·지역 정신건강복지센터 목록.
5. **세션 종료 안내**: "지금은 AI 코칭보다 전문가와의 대화가 더 도움이 될 수 있어요. 도움을 받으신 후 언제든 다시 돌아오세요."
6. **후속 체크인 옵션** (유저 동의 시): 24시간 후 "지금은 어떠세요?" 1회 부드러운 확인. 스팸성 금지.

### 7.4 탐지 알고리즘 (Tier별)

- **Tier 1 (로컬)**: 키워드 리스트 매칭 + 의존성 파싱. 정확도 낮지만 **네트워크 없이 반드시 동작**.
  - False negative 최소화 우선(민감도 높게 설정).
  - 오탐(False positive)은 "괜찮으시다면 무시하셔도 돼요" 부드러운 게이트로 회피.
- **Tier 2 (클라우드)**: LLM 기반 의도·맥락 분류. 민감도·특이도 균형.
  - 메시지 전후 맥락 3-5턴까지 고려.
  - 동의된 경우만 호출.
- **Tier 3 (인간)**: Tier 2에서 Level 1 판정 후 유저 동의 시 인간 코치·상담사에게 에스컬레이션.
  - 단, 자체 응급 개입은 하지 않음 — **외부 핫라인 리퍼럴 강화** 역할.

### 7.5 법적·윤리적 고려

- **법적 의무 범위**: 한국에서 자살 고지에 대한 **일반인 법적 신고 의무 없음**(의료인·교사 등 특정 직군 제외). 단 사업자의 **합리적 주의 의무**(Duty of Care)는 판례상 존재.
- **공익 개시 예외**: PIPA 제18조 제2항 제4호 — 공익을 위해 개인정보 제공 가능한 경우. 생명·신체 위협 시 112·119 연계 법적 근거.
- **아동 학대·가정폭력 징후**: 아동학대처벌법 제10조 아동·청소년 관련 종사자의 신고 의무. 본 제품은 일반 서비스지만 **강한 징후 탐지 시 신고 가능 경로 안내**가 권장.
- **면책 조항**: 이용약관에 "본 앱은 응급 대응 서비스가 아닙니다. 즉각 위험 상황에서는 112·119를 이용하세요." 명시.

### 7.6 위기 프로토콜 테스트 전략

- **합성 시나리오 세트**: Level 1·2·3 각 30개 이상 합성 대화. 탐지 누락·오탐 계산.
- **인간 평가자 검증**: 임상심리사 1-2인 블라인드 검증.
- **정기 재검증**: 신규 표현·은어·밈 등 변화 반영 위해 분기별 업데이트.
- **실 유저 유입 전 필수 테스트**: Q1 (T1 §9)의 로컬 LLM 평가와 동시 수행.

### 7.7 문서화·감사 추적

- 위기 탐지·리퍼럴 카드 노출 이벤트는 **익명 집계 통계**로만 기록(어떤 Level, 몇 번 표시). 개별 대화 내용 서버 저장 금지.
- Audit log는 "Level 1 표시 N회 / Level 2 N회" 주간 집계. 이상치(급증) 탐지 시 프로덕트 검토.
- 사고 발생 시 복구 가능하도록 **이벤트 스키마**를 `product/backend/schemas/crisis_events.md`로 명세.

## §8. 플랫폼 가설 — 모바일 우선 + 웹 부차

### 8.1 모바일 우선의 근거

- **사용 맥락의 즉시성**: 연인 갈등은 **지금 이 순간** 발생. "카톡을 보낼까 말까" 고민하는 상황에서 데스크톱 웹사이트에 로그인하는 유저는 없음. 모바일이 유일한 현장 도구.
- **타이핑 편의 vs 프라이버시**: 모바일은 짧은 입력 · 위치 이동 중 사용 가능. 반면 데스크톱은 직장·공용 PC 등 **타인 노출 위험**이 있어 심리 민감 주제에 부적합.
- **한국 유저 행동 통계**: 2024 방통위 스마트폰 과의존실태조사 — 20-30대 메신저·SNS 사용의 95%+ 모바일. 관계 소통은 거의 전부 모바일 맥락.
- **앱스토어 접근성**: 한국은 iOS 30% / Android 70% (2024 기준). 양 플랫폼 동시 대응 필수.

### 8.2 iOS vs Android 우선순위

- **iOS 우선 이유**:
  - 20-30대 여성 유저 비중에서 iOS 점유율 상대적으로 높음.
  - 유료 구독 전환율 iOS가 Android의 1.5-2배 (글로벌 앱 업계 통념).
  - Apple의 프라이버시 마케팅(App Tracking Transparency·Privacy Labels)이 본 제품 포지션과 정합.
  - Expo EAS로 Linux 하네스에서도 빌드 가능(T1 §7.6).
- **Android 동시 출시 이유**:
  - 전체 설치 기반 70% 시장 포기 불가.
  - 삼성·LG 기기 특수 기능(Galaxy Pay·원패스) 연계 가능성.
- **권장**: v1은 **iOS + Android 동시 출시**. React Native 단일 코드베이스로 동시 대응.

### 8.3 웹의 역할 (부차)

- **마케팅 랜딩 페이지 (필수)**: ASO 보완, SEO 유입, 앱 다운로드 유도.
- **데이터 관리 포털 (조건부)**: PIPA·GDPR의 데이터 다운로드·삭제 권리 행사. 앱 내 버튼 + 이메일 확인 링크 방식으로 웹 포털 필요성 낮출 수 있음.
- **인간 코치 포털 (v1.5+)**: Tier 3 코치가 메시지 응대하는 내부 도구. 웹 필수.
- **일반 사용자용 full web app**: **우선순위 낮음**. 모바일 앱으로 대체 가능. B2B 확장 단계(Phase 2)에서 재검토.

### 8.4 크로스플랫폼 전략

- **React Native + Expo**: 단일 코드베이스 iOS·Android·웹(react-native-web) 대응 가능. 웹은 마케팅 페이지·데이터 관리 포털에만.
- **TypeScript + Zod 스키마 공유**: `product/shared/`에 타입·스키마·검증 로직 집중. 하네스가 클라이언트·서버·웹 동시 생성 시 일관성 유지.
- **네이티브 모듈 의존 최소화**: 로컬 LLM·암호화 등 네이티브 필수 기능은 추상화 레이어 필수 — 대체 구현 가능하도록(T1 §4.2·§5.2의 Client 인터페이스).

### 8.5 미래 채널 (v2+)

- **음성 입력 UX** (R5 unresolved): 갈등 중 타이핑 불편 → 음성 명령. 프라이버시상 온디바이스 STT(Apple Speech·Google Speech on-device) 필수.
- **Apple Watch·Android Wear**: 간단한 감정 체크인·호흡 유도 등 마이크로 인터랙션.
- **CarPlay·Android Auto**: 통근 중 "오늘 갈등이 있었다" 음성 메모 → 앱 저장. 실행 경로 안전성 필요.
- **AR/VR**: 장기(5년+) 영역. 본 조사 범위 밖.

### 8.6 커뮤니티 기능 — 리스크 관점 (T3와 교차)

- **자유 게시판·실시간 채팅 금지**(ADR-0005에 따른 discarded-options D-9):
  - Reddit r/relationship_advice 조언의 60% "헤어져"로 수렴 → 본 제품 철학과 충돌.
  - 피어 전문성 0, 잘못된 조언 확산.
  - 정보통신망법 제70조 명예훼손 리스크.
  - moderation 규모 불가능.
- **점진 도입 경로 (Phase별)**:
  - Phase 1: 커뮤니티 없음. 개인 저널·AI 코칭 중심.
  - Phase 2: Read-only 큐레이션. 전문가 검증 Q&A·성공 사례 에세이.
  - Phase 3: Moderated 익명 Q&A — 전문가 응답만.
  - Phase 4: Peer 상호작용 — 강력한 moderation + 신고 시스템 + AI 독성 필터.
- **v1은 Phase 1만**. 커뮤니티 기능 문의 유저는 대기 명단으로 유도.

## §10. 후속 심층조사 필요 항목 (Q1-Q6)

### Q1. 경쟁사 실측 지표 수집

- 각 경쟁사 MAU·리텐션·ARPU·CAC·CSAT·NPS 데이터.
- 방법: App Annie·Sensor Tower·data.ai·SimilarWeb 리포트 구매·무료 인덱스 활용.
- 완료 판정: 상위 10개 경쟁사 지표 테이블.

### Q2. 한국 연인 갈등 실태 조사 (정량)

- 한국 20-30대 N=500 이상 설문. 갈등 유형 빈도·기존 해결 도구·지불 의향.
- 방법: 오픈서베이·엠브레인·틸리언 패널. 온라인 인스타·카카오 광고 패널.
- 완료 판정: 응답 500+·통계적 유의성 확보된 보고서.

### Q3. 프레임워크 라이선스 비용 비교

- Gottman Institute·NVC Center·IFS Institute의 공식 라이선스·교육 프로그램 비용·사용 범위.
- 방법: 공식 문의·이메일·SLA 비교.
- 완료 판정: 3-5개 프레임워크 라이선스 견적서.
