# T3 — Operator Analyst Raw Report

## 원본 질문 (요지)

> 이 앱을 실제로 사용하는 사람의 심리·행동 패턴·마찰 지점 분석. 관계 갈등 상황의 유저는 일반 SaaS 유저와 근본적으로 다름.

## 조사 방법론

- **문헌 기반**: 갈등 중 인지 부하·Flooding·자기보호 편향(Gottman·Siegel·Gross) 문헌 리뷰. Consumer Reports·Mozilla *Privacy Not Included* 관계/건강 앱 조사.
- **공개 후기 경향성 분석**: 경쟁 앱(Lasting·Paired·Replika·트로스트) App Store 후기 상위 키워드 집계. Reddit r/relationship_advice·에브리타임·블라인드 관계 게시판의 질문 유형.
- **페르소나 모델링**: 3 페르소나 추출 — 파워 유저(민지)·위기 first-time(준호)·장기 복귀(수빈).
- **9단계 유저 여정**: 트리거→탐색→첫 세션→리텐션→공유→유료 전환→위기→회복→장기 복귀.
- **감정 안전 설계**: 위기 탐지·UI 톤·모호성 회피·리퍼럴 경로 UX.
- **상업화 수용성**: 유료화 타이밍·가격 민감도·한국 인앱결제 특수 (R6 교차).

## §1. 관계 갈등 중 유저 심리 — 일반 SaaS와 다른 이유

### 1.1 갈등 순간의 생리학 — Flooding

John Gottman의 **Emotional Flooding** 이론: 갈등 중 심박수 100bpm 이상·코르티솔 급증 시 전두엽 기능 저하. 이 상태에서는:

- **복잡한 UI 탐색 불가**: 메뉴·탭·세팅 접근 실패율 급증.
- **긴 텍스트 읽기 불가**: 3-4줄 이상 설명은 스킵.
- **자기 입력 어려움**: 감정 상태를 단어로 표현할 여유 없음. 버튼·이모지·슬라이더 선호.
- **결정 회피**: "유료 가입"·"파트너 초대" 같은 무게 있는 선택을 그 순간에 못함.

**앱 설계 함의**:
- **One-tap 진입**: 홈 화면에서 "지금 힘들어요" 1회 탭으로 코칭 흐름 시작.
- **감정 슬라이더 + 이모지**: 1-10 슬라이더, 감정 얼굴 6-8개 선택. 자유 텍스트는 선택.
- **읽기 분할**: 한 화면당 텍스트 40-60자 이내. 긴 조언은 "더 보기" 접기.
- **선택 부담 감소**: 세션 중 유료 권유·파트너 초대 금지. 세션 종료 후 쿨다운 시간 두고 제안.

### 1.2 자기보호 편향 (Self-Protective Bias)

갈등 중 유저는 **자기 정당화** 방향으로 인지 왜곡. 본인 입력이 한쪽 당사자 시점의 재구성임을 앱은 인식해야 함.

- **"객관적 판단" 요청 금지**: "상대방이 잘못한 거죠?" 질문에 "네"라고 동조하면 강화·확증. 중립 복귀 필요.
- **재구성 유도**: "상대방은 어떤 기분이었을까요?"·"그 순간 상대에게 가장 중요한 건 뭐였을까요?"형 질문으로 관점 전환.
- **감정 수용 먼저**: 관점 전환은 감정이 먼저 안전해진 이후 가능. "그렇게 느낄 만하네요" → "시간이 지나고 나면 이런 측면도 볼 수 있어요" 순서.

**앱 설계 함의**:
- **2단계 플로우**: (1) 감정 수용·진정 단계 → (2) 관점 확장·스크립트 단계. 2단계로 건너뛰기 금지.
- **재구성 거부 시 후퇴**: "지금은 그럴 수도 있어요" 안전 응답으로 세션 유지. 집요한 재구성 시도는 유저 이탈 유발.

### 1.3 프라이버시 불안 (Privacy Anxiety)

Consumer Reports 2023 — 관계 앱 유저 **58%가 "파트너가 볼까 걱정"**. 일반 앱(15%) 대비 4배.

- **앱 아이콘·이름 자체가 노출 리스크**: "연애 상담"·"커플 코칭" 직접 명시 앱을 홈 화면에 두기 부담.
- **푸시 알림 미리보기**: 잠금 화면에 메시지 일부 노출 → 파트너·가족 우연히 볼 가능.
- **지문·Face ID 요구 시 의심**: "왜 로그인마다 잠그지?" — 역으로 의심 유발 가능.
- **결제 내역 노출**: 공동 통장·가족 확인 앱으로 노출.

**앱 설계 함의**:
- **중립 브랜드**: "Coach"·"Kora"·"Balance"·"Nuance" 같은 중립 명. 관계 특정성 낮은 아이콘.
- **잠금 화면 푸시 문구 중립화**: "새 메시지가 있어요"·"오늘의 체크인" 수준.
- **앱 실행 시 앱 내 잠금 옵션** (Face ID·PIN·지문): 옵션이지 강제 아님. 유저가 토글 가능.
- **가명 결제 옵션**: 가능한 범위에서 결제 명칭을 중립화("Kora Plus" 등).

### 1.4 감정 취약성 (Emotional Vulnerability)

첫 세션에 울거나 심하게 괴로워하는 유저 예상. 일반 SaaS와 달리 **감정 반응이 제품 경험**.

- **울음·오열 대응**: 긴 대기 없이 짧은 공감 응답. "괜찮아요, 천천히 하셔도 돼요" 상시 carousel.
- **세션 중단 허용**: "지금은 그만할래요" 버튼 항상 접근 가능. 중단 시 다음 단계 강요 금지.
- **공감 응답의 기계적 반복 회피**: "힘드시겠어요"·"이해해요"만 반복하면 오히려 상처. 응답 다양성 필수.

### 1.5 관계적 수치심 (Relational Shame)

"내가 이런 걸로 앱을 쓴다니"·"상담받는 수준인가"형 자기 판단이 진입 장벽.

- **정상화 카피**: 온보딩에 "연인의 80%가 같은 갈등을 겪어요" 통계 기반 안내.
- **자기 판단 언어 삭제**: "문제"·"이상"·"심각" 같은 negative framing 최소화. "갈등"·"어려움"·"불편" 선호.
- **성공 서사**: 익명 유저 사례(전문가 감수) — "비슷한 고민을 이렇게 풀어간 사람들이 있어요."

### 1.6 일반 SaaS UX 원칙의 수정

| 일반 SaaS 원칙 | 관계 코칭 앱 수정 |
|---|---|
| 기능 발견성 극대화 (Discoverability) | **절제** — 세션 중 다른 기능 노출 억제 |
| A/B 테스트로 전환율 최적화 | **감정 안전 확보 후** — 위기 상태 유저 실험 대상 금지 |
| 푸시 알림 리텐션 극대화 | **보수적** — 주 2-3회 이하, 타이밍 민감 |
| Onboarding에서 모든 기능 소개 | **최소** — 첫 세션 진입 마찰 최소화 |
| 소셜 공유 활성화 | **기본 비활성** — 의도적 opt-in |
| 게이미피케이션(뱃지·스트릭) | **매우 조심** — 감정 노동을 성취로 프레이밍은 자칫 불건강 |

## §2. 3개 페르소나 — 민지(파워)·준호(위기 first-time)·수빈(장기 복귀)

페르소나는 **단일 전형 유저**가 아닌 "설계 의사결정 충돌 시 우선순위 판단용 원형". 본 조사는 3인 페르소나 + **1순위 준호** 결론.

### 2.1 페르소나 A — 민지 (파워 유저, 28세)

- **배경**: 서울 거주, 대기업 마케터, 3년차 연애 중. 자기계발 책·팟캐스트·코칭 앱 다수 사용 경험.
- **사용 패턴**:
  - 주 3-5회 접속. 갈등 없을 때도 "오늘의 체크인"·저널링 활발.
  - 심리학·커뮤니케이션 이론에 익숙. Gottman·NVC·MBTI·애착유형 용어 편안.
  - 앱을 **관계 성장 도구**로 활용 — 갈등 해결뿐 아니라 관계 풍부화.
  - 데이터 다운로드·통계 대시보드 등 투명성 기능 선호.
- **Goals**:
  - 관계 만족도 유지·향상. 자기 이해·성숙.
  - 파트너와 공동 사용으로 소통 언어 동기화.
- **Pains**:
  - 얕은 조언 (이미 알고 있는 수준)에 실망. 깊이 있는 프레임워크·맞춤 제안 기대.
  - 타 앱의 지나친 단순화·"항상 서로 이해해주세요" 진부함.
- **Willingness-to-Pay**: 높음(월 9,900-24,900 수용). 단 품질 기대 높음 — 실망 시 해지 빠름.
- **크리티컬 결정 시 가중치**: **2순위** (Phase 1 최적화 대상 아님).

### 2.2 페르소나 B — 준호 (위기 first-time, 26세) — 1순위

- **배경**: 수도권 거주, 중소기업 개발자, 1년차 연애. 관계 상담·코칭 앱 **경험 없음**. 갈등 후 구글에 "여친이랑 싸웠을 때"·"화해하는 법" 검색으로 첫 유입.
- **사용 패턴**:
  - 갈등 순간에 **처음 설치** — 세션당 고강도 사용 → 해결 후 간헐적 재방문.
  - 자기보고 감정 어휘 부족. "그냥 짜증나요"·"모르겠어요"형 응답 많음.
  - 복잡한 UI·개인화 설정에 인내심 낮음. "지금 당장 답"이 필요.
  - 공유 기능·파트너 초대에 **저항** — 그 순간에 파트너와 공유할 심리 상태 아님.
- **Goals**:
  - 당장의 갈등 진정·상대에게 할 말 다듬기.
  - "내가 이상한 건가?"에 대한 safety check.
- **Pains**:
  - 진입 장벽 하나라도 넘으면 이탈. "회원가입 4단계" 시도 시 70%+ 이탈 예상.
  - 본인 프라이버시 의식 강함(§1.3). "파트너가 보면 어떡하지" 걱정.
  - 심리학 용어·학술 프레임워크 언급 시 낯설음·거부감.
- **Willingness-to-Pay**: 즉시 지불 의향 **높음**(위기 순간 가치). 단 일단 해결되면 해지율 높음 → **리텐션 전략 분리** 필요.
- **크리티컬 결정 시 가중치**: **1순위**.

**왜 1순위인가**:
- 시장 크기: 관계 문제로 "처음" 도구를 찾는 사람이 압도적 다수 (AppsFlyer 2024 기준 first-time 사용자 60%+).
- Time-sensitive 니즈 = 즉시 지불 의향 최고.
- Viral/Referral: 문제 해결 경험자 추천이 가장 강력한 마케팅.
- B 기준 설계는 A·C 수용 가능, 역은 성립 안 함 (낮은 복잡도 → 높은 복잡도로 확장 가능, 역은 불가).

### 2.3 페르소나 C — 수빈 (장기 복귀, 33세)

- **배경**: 결혼 5년차, 자녀 1. 과거 커플 코칭 앱·독서 모임 경험. 이혼 상담도 고려했었음.
- **사용 패턴**:
  - 월 2-4회 접속. 일과 후 잠들기 전 10-20분 저널링·리뷰.
  - 깊은 주제 다룸 — 원가족 패턴·어린 시절 경험·가치관 불일치.
  - 타 도구(오프라인 상담·도서·명상 앱)와 병행.
- **Goals**:
  - 장기 패턴 파악·반복 갈등 근본 탐색.
  - 이혼 vs 지속 결정의 자기 정리.
- **Pains**:
  - 얕은 조언·일회성 팁 무용. 이미 많이 읽고 시도.
  - 앱 내 자료의 지루함 — 같은 내용 반복이면 이탈.
  - 개인화 부족 — "내 맥락을 다시 설명해야 하는" 불편.
- **Willingness-to-Pay**: 중간-높음. 프리미엄·인간 코치 티어에 매력 느낌.
- **크리티컬 결정 시 가중치**: **3순위** (Phase 1.5+ 리텐션 전략에서 중요).

### 2.4 페르소나 간 설계 충돌 우선순위

| 결정 사안 | 민지 A 선호 | 준호 B 선호 | 수빈 C 선호 | 우선 결정 |
|---|---|---|---|---|
| 온보딩 길이 | 상세(5-7화면) | 최소(1-2화면) | 중간(3-4화면) | **준호 B 기준 최소** |
| 심리학 용어 사용 | 환영 | 거부감 | 익숙 | **준호 B 기준 자연어 우선** + 심화 모드 옵션 |
| 파트너 초대 우선순위 | 높음 | 낮음 | 중간 | **옵트인, 초반 비강제** |
| 데이터 대시보드 노출 | 원함 | 관심 낮음 | 원함 | **설정 탭으로 분리** |
| 유료 전환 타이밍 | 빠름 | 위기 직후 | 중간 | **준호 B 기준 첫 세션 후 24h+** |

### 2.5 다른 세그먼트 (페르소나 미채택)

- **대학생 20-23세**: 앱 진입 가능하지만 지불 의향 낮음. 준호 유입 채널에서 자연 유입 → freemium 무료 기능만 대상.
- **50대 이상**: 관계 코칭 앱 문화 자체 낯섦. Phase 3+ 타겟.
- **이혼 고려 단계 깊은 유저**: 페르소나 C의 특수 경우. 전문 상담 리퍼럴 우선.
- **LGBTQ+ 커플**: 본 조사 미포함 (P-T2-8).

## §3. 9단계 유저 여정 (페르소나 B 준호 기준)

1순위 페르소나 준호의 여정을 **9단계**로 분해. 각 단계에서 유저 상태·앱 역할·이탈 리스크·개선 레버리지를 기록.

### S1. 트리거 (Trigger)

- **상태**: 방금 싸움·불편한 대화 종료 직후. 감정 고조·생각 정리 안 됨.
- **앱 외부**: 친구 조언·유튜브 검색·네이버 지식iN·구글 "여친이랑 싸웠을 때" 검색.
- **앱 역할**: 아직 없음 (이 단계에 앱 존재 인지 無).
- **이탈 리스크**: 100% (미진입).
- **레버리지**: SEO·ASO·유튜브 연애 채널 스폰서십. 한국 검색어 공략: "남친 화났을 때", "여자친구 서운해할 때", "카톡 답장 어떻게".

### S2. 탐색 (Discovery)

- **상태**: 구글·네이버·앱스토어 방문. 여러 앱·블로그·커뮤니티 비교.
- **앱 역할**: 랜딩 페이지 + 앱스토어 페이지.
- **이탈 리스크**: 60-80% (다른 앱 선택·유료 부담·검색 포기).
- **레버리지**:
  - 랜딩 헤드라인 — 페르소나 B 언어로. "지금 싸우고 화해하고 싶다면" > "관계 성장 플랫폼".
  - 앱스토어 스크린샷 첫 3장 — 실제 화면 + 한 문장 핵심 가치.
  - "이 앱은 상담이 아닙니다. 갈등 중 대화 정리를 돕는 도구입니다." 명확한 경계.
  - 프라이버시 카피 — "대화는 기기에 저장됩니다. 서버로 보내지 않아요" (Branch A/Hybrid 마케팅 훅).

### S3. 첫 세션 (First Session — Time-to-First-Value, TTFV)

- **상태**: 앱 설치·오픈. 감정 여전히 격앙. 회원가입에 저항.
- **앱 역할**: **5초 내 코칭 시작**. 회원가입 없이 즉시 세션 진입.
- **이탈 리스크**: 70%+ (회원가입 벽 1회만 세워도 이탈 급증).
- **레버리지**:
  - **익명 첫 세션**: 이메일·전화번호 요구 없음. 닉네임 선택만.
  - 입력 방식 — 이모지·감정 슬라이더 1-2개 선택 후 자유 서술.
  - 첫 응답 — 공감 먼저, 조언 후. "많이 답답하셨겠어요. 어떤 말이 가장 속상했는지 들려줄 수 있을까요?"
  - 10-15분 내 **1개 구체 행동**(카톡 초안 제안 등) 나옴 → TTFV 달성.
  - 세션 종료 시 "기록을 저장할까요?" 저장 옵션 + "기록 없이 종료" 옵션.

### S4. 첫 만족 직후 (Immediate Aftermath)

- **상태**: 위기 어느 정도 진정. "도움이 됐다" 감정.
- **앱 역할**: 가벼운 저장 제안 + 리텐션 시드.
- **이탈 리스크**: 40% (해결되면 앱 삭제 경향).
- **레버리지**:
  - 성과 저장 — 저널 자동 요약(1-2 문장) "오늘은 이런 감정을 느꼈고, 이런 제안으로 마무리했어요."
  - 다음 접속 훅 — "3일 후 같은 감정이 올라오면 찾아오세요" (강요 없는 초대).
  - 이메일·푸시 미가입 유도 — "내일 아침 체크인 알림 받을까요?" **단일 질문 opt-in**.

### S5. 리텐션 (Retention, Day 1-30)

- **상태**: 갈등 잠잠. 관심 감소.
- **앱 역할**: 가볍고 실용 콘텐츠. 감정 체크인·짧은 팁·기사 요약.
- **이탈 리스크**: 60-70% (30일 리텐션 20-30% 목표).
- **레버리지**:
  - **주간 감정 체크인** — 주 1회 2-3분. 부담 최저.
  - **맞춤 콘텐츠** — 페르소나 B의 초기 입력(갈등 유형) 기반.
  - **스트릭 없음** — §1.6 원칙. 대신 "이번 주 소중했던 순간 한 가지"형 부드러운 저널.
  - **재난 트리거** — 다음 싸움 발생 시 **즉시 감지**(앱 열림 빈도·감정 입력 패턴)하여 맞춤 대응.

### S6. 파트너 공유 (Partner Share — Optional)

- **상태**: 여유·관계 개선 의지 형성. 공유 고려.
- **앱 역할**: 공유 기능 자연스럽게 소개. 강제 없이 유저 주도.
- **이탈 리스크**: 낮음(이 단계 도달 유저는 헤비 유저). 단 파트너 초대 실패 시 실망.
- **레버리지**:
  - 초대 UX — 파트너에게 보낼 메시지 미리보기 + 커스텀 가능. "함께 써보자" 반감 최소화.
  - 파트너 수락 UX — 독립 세션 + 공유 공간 분리. 각자 프라이버시 유지.
  - 공동 과제 — "오늘 고마웠던 것 한 가지씩" 공유 루틴.

### S7. 유료 전환 (Conversion)

- **상태**: 30-60일 사용 후. 가치 인정·지속 의지.
- **앱 역할**: freemium → paid 자연스러운 전환 제시.
- **이탈 리스크**: 80-90% (무료 티어만 계속 사용).
- **레버리지**:
  - 유료 기능의 **명확한 가치 제안** — "월 9,900원으로 Tier 2 클라우드 코칭 무제한 + 주간 관계 리포트".
  - 할인 없이 가치로 설득 우선. 할인 남발 시 브랜드 가치 하락.
  - 7일 무료 체험 — Tier 2 기능 시연. 자동 청구 투명 공지.

### S8. 위기 재발 (Crisis Recurrence)

- **상태**: 이전 갈등 패턴 재발·또는 새 유형 갈등. 앱 재접속.
- **앱 역할**: 과거 맥락 기억·연속성 제공.
- **이탈 리스크**: 30% (이 단계 접근 유저는 상당한 신뢰).
- **레버리지**:
  - "지난번에는 이렇게 풀었어요" 맥락 제시 (기억 연속성).
  - 유료 tier라면 Tier 2·3 자연스러운 제시.
  - Tier 3 (인간 코치) 안내 — 반복 패턴 감지 시.

### S9. 장기 복귀 (Long-term Return) — 페르소나 C로 이행

- **상태**: 결혼·이사·임신·이직 등 생애 변화. 관계 코칭 재수요.
- **앱 역할**: 과거 데이터 기반 깊은 분석·패턴 리포트 제공.
- **이탈 리스크**: 70% (관계 해소·타 도구 전환).
- **레버리지**:
  - **장기 리포트** — 1년·3년 관계 패턴 시각화.
  - 부부·가족 확장 기능 (Phase 2 홍보 연계).

## §4. 프라이버시 신뢰 신호 포트폴리오

Consumer Reports 58% 불안(§1.3)을 완화할 **구체 신뢰 신호** 13개. 한두 개 확보로 부족 — 다층 포트폴리오가 필요.

### 4.1 기능 레벨 신호 (In-Product)

- **N-1. 앱 잠금**: PIN·생체 인증. 진입 장벽 체감으로 안심.
- **N-2. 잠금 화면 푸시 중립화**: 미리보기 비공개. 기본 ON.
- **N-3. 데이터 다운로드 버튼**: 설정 한 단계 내. 1클릭 JSON export.
- **N-4. 계정 삭제 버튼**: 같은 위치. 30일 유예 옵션·즉시 삭제 옵션.
- **N-5. Tier별 동의 토글**: 클라우드 전송 여부를 유저가 끄고 켤 수 있음.
- **N-6. 세션별 "이 대화는 어디로 가나요?" 인디케이터**: 작은 아이콘으로 Tier 표시.
- **N-7. 대화 스냅샷 미리보기**: 유료 기능으로 전송 직전 마스킹 미리보기.

### 4.2 정책 레벨 신호 (Policy)

- **N-8. 프라이버시 정책의 인간 언어**: 법률 용어 나열 아닌, 한국어 일상체 요약 + 시각 다이어그램. Apple Privacy Labels·Google Data Safety 표기와 정합.
- **N-9. 수집하지 않는 것 명시**: "광고 트래커 없음"·"파트너 데이터 공유 안 함"·"제3자 분석 SDK 없음" 체크리스트.
- **N-10. 투명성 리포트**: 분기별 외부 데이터 요청 받은 건수·거부 건수(초기는 0이 대부분일 것).

### 4.3 브랜드·UX 레벨 신호 (Brand)

- **N-11. 앱 아이콘·이름 중립성**: §1.3 원칙. 홈 화면 노출 부담 최소.
- **N-12. 창립자·팀 공개**: 투명 인물 정보. 심리 전문가 자문단 공개(R8).
- **N-13. 제3자 감사 인증**: SOC 2 Type II·ISO 27001 장기적 획득. v1 달성 어려우면 로드맵 공지.

### 4.4 신호별 획득 난이도·효과

| 신호 | 획득 난이도 | 인지 효과 | v1 필수 여부 |
|---|---|---|---|
| N-1 앱 잠금 | 낮음 | 높음 | 필수 |
| N-2 푸시 중립화 | 낮음 | 높음 | 필수 |
| N-3 데이터 다운로드 | 중간 | 중간 | 필수(GDPR·PIPA) |
| N-4 계정 삭제 | 중간 | 중간 | 필수(GDPR·PIPA) |
| N-5 Tier 토글 | 중간 | 매우 높음 | 필수(Hybrid 핵심) |
| N-6 Tier 인디케이터 | 낮음 | 높음 | 강력 권장 |
| N-7 마스킹 미리보기 | 중간 | 높음 | 강력 권장 |

### 4.5 신호 조합의 상승 효과

- N-5 Tier 토글 + N-6 Tier 인디케이터 + N-7 마스킹 미리보기 = **Tier 라우팅 투명성 3종 세트**. Hybrid 아키텍처의 핵심 가치 전달.
- N-1 앱 잠금 + N-2 푸시 중립화 + N-11 브랜드 중립 = **파트너·가족 노출 최소화 세트**. §1.3 불안 직접 대응.
- N-3 데이터 다운로드 + N-4 계정 삭제 + N-9 수집하지 않는 것 = **데이터 통제권 세트**. GDPR·PIPA 법적 준수 + 신뢰.

## §6. 복잡도 수용 임계 (Complexity Tolerance Thresholds)

갈등 상황에서 유저가 견딜 수 있는 UX 복잡도의 상한. §1.1 Flooding 기반.

### 6.1 정량 임계 (첫 세션)

- **화면 전환 횟수**: 첫 세션 완료까지 **최대 5화면**. 초과 시 이탈률 선형 증가.
- **터치 횟수**: 코칭 첫 응답까지 **최대 7 탭**. 회원가입 0-1 화면 가정.
- **텍스트 분량**: 한 화면 **한글 60-100자** 이내. 초과 시 "더보기" 접기.
- **입력 필드**: 첫 세션 **최대 2개** 자유 입력. 초과 시 이모지·슬라이더 대체.
- **대기 시간**: LLM 응답 **3초 이내 첫 단어**·스트리밍. 5초+ 대기 시 이탈.
- **알림 배지**: 첫 세션 중 뱃지·통계·성취 표시 **금지**.

### 6.2 복잡도 증가 허용 시점

- **세션 종료 이후 쿨다운 30분+**: 추가 기능 안내 허용.
- **두 번째 세션부터**: 설정·개인화·파트너 초대 등 점진 도입.
- **30일 사용 이후**: 심층 분석·대시보드·장기 리포트 접근.

### 6.3 페르소나별 임계 차이

| 지표 | 민지 A | 준호 B | 수빈 C |
|---|---|---|---|
| 첫 세션 최대 화면 | 7 | **5** | 6 |
| 설정 옵션 탐색 의지 | 높음 | 낮음 | 중간 |
| 학술 용어 노출 허용 | 높음 | **낮음** | 중간 |
| 리포트 요구 상세도 | 높음 | 낮음 | 높음 |

**설계 결정**: **준호 B 임계를 v1 기본**. A·C는 설정·심화 모드 opt-in.

### 6.4 복잡도 관리 UI 패턴

- **Progressive Disclosure**: 기본 단순 → 설정에서 확장. 첫 화면에 모든 것 보여주지 않음.
- **Smart Defaults**: 기본값이 페르소나 B 최적화. 설정 변경 필요성 최소.
- **Contextual Menus**: 상황별 필요한 옵션만 노출. 컨텍스트 밖 옵션 숨김.
- **Skip·Later 버튼**: 필수 아닌 단계에 항상 제공.
- **Retreat 버튼**: 모든 화면에 "이전"·"나가기" 단일 탭 가능.

### 6.5 복잡도 vs 가치 교환 곡선

- 단순 기능(메시지 리라이트·감정 체크인)은 **준호 B 임계 이내로 유지** — 복잡도 희생 금지.
- 심층 기능(장기 패턴 분석·파트너 공동 세션)은 임계 **유저가 주도적으로 확장**하는 구조 — 강요 없음.
- "복잡도 상한"은 **각 단일 상호작용 기준**. 앱 전체의 기능 수 자체를 제한하는 것이 아님.

## §7. 감정 안전 설계 (Emotional Safety Design)

앱 전체를 관통하는 감정적 안전 레이어. T2 §6 경계선과 T2 §7 위기 프로토콜을 UX 시점에서 재조직.

### 7.1 톤 가이드 (Tone of Voice)

- **제1 원칙 — 판단 없음 (Non-judgmental)**: "잘못하셨네요"·"그건 이상해요" 금지. 모든 유저 감정 수용 전제.
- **제2 원칙 — 공감 우선 (Empathy-First)**: 조언 전 반드시 감정 인정 1-2문장. "답답하셨겠어요·상처받으셨네요·혼란스러우시겠어요".
- **제3 원칙 — 겸손 (Humble)**: "확신"·"반드시"·"당연히" 어휘 회피. "~일 수 있어요"·"~은 어떨까요" 선호.
- **제4 원칙 — 한국어 자연체**: 번역투·학술투 회피. 친구에게 말하듯. 단 과도한 반말·애교체 금지.
- **제5 원칙 — 짧게**: 장문 금지. 3-5 문장 단위로 쪼개서 스트리밍.

### 7.2 금지 표현 목록 (Tone Blocklist)

- "당신은 ~한 사람이네요" (성격 단정)
- "상대방이 ~한 걸 보니" (제3자 판단)
- "헤어지는 게 답이에요" (관계 결정 단정)
- "이건 학대예요·폭력이에요" (진단·판단 — 단 Level 1 위기 키워드는 별도 프로토콜)
- "제가 경험해봐서 아는데" (AI의 경험 공유 금지)
- 과도한 느낌표·이모지·이모티콘 (진정성 훼손)

### 7.3 모호성 회피 (Ambiguity Avoidance)

- 조언이 **행동 수준**으로 구체적이어야. "잘 얘기해보세요" 같은 공허한 조언 금지.
- 대신: "오늘 저녁 카톡으로 '~'라고 보내보면 어떨까요" 수준 구체 제안.
- 제안 수용·거부·수정 옵션: "이대로 보낼래요·수정할래요·다른 제안 볼래요".

### 7.4 감정 돌봄 요소 (Care Elements)

- **호흡 가이드**: Level 2 위기·고통 탐지 시 3-5분 호흡 가이드 제시. 강요 없음.
- **자기 연민 문구 (Self-compassion)**: 세션 종료 시 "지금 이 순간을 지나고 있는 것만으로도 충분해요" 같은 부드러운 마무리.
- **성찰 일지**: "오늘 나를 가장 힘들게 한 것"·"그럼에도 내가 잘한 것" 양면 질문.

### 7.5 상황별 안전 규칙

- **울음·오열 감지 시** (입력 패턴·키워드 기반): 긴 응답·추가 질문 금지. 짧은 공감·쉼의 제안.
- **상대 비난 폭주 시**: 내용 확인 후 "많이 속상하셨네요" 공감 + 재구성은 시간 두고 제시.
- **자기 비난 패턴 시**: "자신을 그렇게 보실 필요 없어요" 가볍게 개입. 과도한 역조언 금지.

### 7.6 감정 안전 검증 메커니즘

- **합성 시나리오 테스트**: 고강도 감정 표현 30+ 시나리오 응답 품질 주기적 체크.
- **유저 피드백 반영**: 세션 후 "도움이 되었나요? 상처가 되지는 않았나요?" 2-축 간단 평가.
- **LLM 응답 사후 검증 Hook**: `validate_tone_and_safety.py` (T1 C2 계열 확장) — 응답 내 금지 표현 탐지.

### 7.7 감정 안전과 효능감(Efficacy)의 균형

"너무 부드럽기만 하면 실제 변화 촉진 약함" 역의 우려. 해결:

- **공감 → 관점 전환 → 행동** 3단계 흐름 유지.
- 공감만 반복하면 단계 정체 → "이제 ~을 시도해볼 준비가 되셨어요?" 부드러운 진행 제안.
- 유저가 "이제 괜찮아요, 다음으로" 주도 시에만 관점 전환·행동 단계 이동.

## §8. 커뮤니티·소셜 리스크

T2 §8.6과 교차. 본 섹션은 **유저 심리·실패 모드** 관점에서 재검토.

### 8.1 피어 조언 실패 패턴 (Reddit 60% 현상)

Amaro et al. (2023) — r/relationship_advice 조언의 60%가 "헤어져(break up)"로 수렴. 이유:

- **수집 편향**: 피해자 시점의 일방적 서사만 공개. 상대 맥락 결여.
- **익명 군중 심리**: 익명자는 급진적 조언에 사회적 비용 없음. "그냥 차버려"형 조언 쉬움.
- **도덕적 정체성 소비**: 타인의 관계 평가로 자기 도덕 우위 느낌. 장기 관계 성장엔 무도움.

→ **본 제품은 피어 조언 채널 금지**. Phase 1 커뮤니티 없음.

### 8.2 비교 유도 위험 (Social Comparison)

Vogel et al. (2014) — SNS 비교가 자존감·관계 만족도 저하.

- "다른 사람은 이렇게 쉽게 해결하는데"·"다른 커플은 안 싸우는데" 유도 위험.
- 앱 내 타인 사례 노출 시 **편집된 긍정 서사**로 비치면 비교 스트레스.

→ **타인 사례 사용 원칙**:
- 익명 + 다양성 + 과정 중심(결과 중심 아님).
- "매주 싸우다가 OO을 시도하며 조금 달라졌어요"형 현실 서사.
- 완벽 해결 서사 회피.

### 8.3 독성 표현·혐오 (Toxic Content)

커뮤니티 도입 시 필연적 문제.

- **혐오 발언**: 젠더·지역·정치 혐오. 한국 온라인 커뮤니티에서 고빈도.
- **성적 괴롭힘**: 특히 여성 유저 대상.
- **개인정보 요구·스토킹**: 관계 갈등 맥락 특히 위험.
- **상업 스팸·외부 서비스 유도**.

→ **Phase 2+ 커뮤니티 도입 전제**:
- Real-time AI 독성 필터 (한국어 특화).
- 인간 moderator 24/7.
- 신고·차단·영구 정지 워크플로우.
- 규모 감당 안 되면 출시 연기.

### 8.4 법적 리스크

- **정보통신망법 제70조 명예훼손**: 사실 적시 명예훼손도 처벌 대상. "우리 남친이 이런 행동 해"류 공개 글이 법적 쟁점화 가능.
- **개인정보 유출**: 제3자(파트너·친구·직장 동료) 식별 가능 정보 공개 시 PIPA 위반.
- **청소년 보호**: 선정적·폭력 콘텐츠 필터링.
- **자해·자살 조장 콘텐츠**: 정보통신에 관한 자해·자살 조장 정보 제공 시 형사 처벌.

→ 커뮤니티 도입 시 **법무 검토 필수**. 분기별 리뷰.

### 8.5 대안 — 구조화된 공유

완전 금지 대신 구조화된 비-피어 공유:

- **"오늘의 연습 과제 공유" 옵션**: 익명·카테고리 태그·전문가 검토. 댓글 없음.
- **전문가 검증 에세이**: 임상심리사 작성 글 모음. 질문 불가 게시.
- **파트너 공동 공간**: 오직 본인-파트너 둘만의 공유. 외부 확장 없음.

### 8.6 커뮤니티 로드맵 (Phase별)

- **Phase 1 (v1)**: 커뮤니티 없음.
- **Phase 2 (v1.5)**: Read-only 큐레이션 — 전문가 검증 콘텐츠만.
- **Phase 3 (v2)**: Moderated Q&A — 전문가 응답만.
- **Phase 4 (v3+)**: Peer 상호작용 — 강력한 moderation + AI 독성 필터 + 신고 시스템.

각 Phase 진입 전 **유저 리서치 + 법무 검토 + moderation 리소스 확보** 필수.
